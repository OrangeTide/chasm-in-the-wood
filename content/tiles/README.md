# Authored tiles

The world is drawn from one mesh per tile kind, per environment. Each is an authored
voxel model loaded from this directory when present, and a generated placeholder (see
`src/render/prims.pas`) when absent. So authored art drops in one file at a time; a
kind with no file stays procedural until its file lands. The loader is `TileKitLoad`
in `src/render/tilekit.pas`.

## Layout

```
content/tiles/<env>/<kind>.vox
```

- `<env>` is one of `dungeon`, `forest`, `town`.
- `<kind>` is one of `floor`, `wall`, `door`, `doorleaf`, `stairup`, `stairdn`, `prop`.

Every combination is optional. For example, `content/tiles/dungeon/floor.vox` replaces
the generated dungeon floor, while a missing `content/tiles/forest/door.vox` leaves the
forest door as the generated arch.

| Kind | What it is | Placeholder |
| --- | --- | --- |
| `floor` | The walkable ground plate. | A plate one tile tall. |
| `wall` | The solid wall block. | A taller plate. |
| `door` | An open, walkable doorway. | An arch. |
| `doorleaf` | A shut (locked) door that bars the way until a key opens it. | A plate filling the frame. |
| `stairup` | Steps climbing toward the level above. | A short flight of steps. |
| `stairdn` | Steps descending toward the level below. | The same flight, reversed by the drawer. |
| `prop` | A free-standing object standing in a cell (a tree, a barrel): it blocks the body but shows no wall face, and draws as a centred model over the floor. | A trunk with a ball canopy. |

## Conventions

- **Format**: a `.vox` file (MagicaVoxel format), read by `voxfile.pas`. The
  file is z-up (height along the file's z); the loader bakes it into the engine's y-up.
- **Footprint and pitch**: author every tile on a **24-voxel square footprint** (`TILE_GRID`),
  one cell. A cell is 1.5 m and a voxel is 0.0625 m (see `docs/asset-pipeline.md`), so a
  voxel is the same physical size tile to tile and bars, mortar lines, and trim line up
  across the seams. The drawer fits any footprint to the cell (`TILE / Sx`), but a tile
  authored at some other width would render with a different voxel size and break that
  alignment. A styloo kit module is 96 voxels, which is four cells; it is sliced to cell
  tiles. Art taller than `TILE_MAXH` = 256 is clamped.
- **Heights**: height is free up to `TILE_MAXH`; a wall need only be as tall as the look
  wants. The coarse placeholders stand `TILE_WALLH` = 40 and stairs `TILE_STEPH` = 30 at
  their own `TILE_FOOT` = 16 resolution, so they do not set the authored height.
- **Stairs**: the steps run along the tile's +x axis; the drawer reverses them for the
  down variant, so one model can serve both if symmetric.
- **Props**: a `prop` is not fitted to the cell like the other kinds. The drawer stands it
  at the object voxel-unit (`VU`), centred on the cell with its feet on the floor, so an
  authored prop keeps its own proportions and may rise taller than a wall. Author it on the
  same 24-voxel footprint to sit within a cell (a wider base would overhang its neighbours),
  but let the height run as tall as the object needs. Numbered variants (`prop2.vox`, ...)
  cycle per cell, so a mix reads as a stand of trees rather than a row of clones.

## Converting kit assets

Tiles are produced by the asset converter, not by hand. The pipeline (stage the kit
sources, then convert at each kit's scale) and the pinned world scale are documented in
`docs/asset-pipeline.md`; the tile slot each source fills is listed in `tools/assets.txt`.
The voxel size (0.0625 m) was chosen so the styloo prison bars resolve as even voxel
columns: at that size a bar is about one voxel with a few voxels between bars, where coarser
sizes merge them.
