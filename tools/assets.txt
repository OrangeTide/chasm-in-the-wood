# Asset manifest for tools/convert. See docs/asset-pipeline.md.
#
#   asset <kit> <source> <output.vox> [surface] [offset=vx,vy,vz] [cell] [celloff=ox,oy]
#
# <kit> names a row in tools/kits.txt (which sets the scale and the up-axis).
# <source> is relative to ASSET_ROOT, the directory holding the extracted kit sources
# (a .fbx/.gltf/.glb goes through assimp, a .obj is used directly). <output.vox> is
# relative to the working directory. surface keeps the bare shell (grates, foliage);
# offset sets the per-axis sampling phase (half a voxel centres a standalone model).
# cell slices a kit module down to one cell tile; celloff picks which cell of the module
# (voxel origin ox,oy), so the same module yields several variants (floor, floor2, ...).
# cellfill extrudes a thin face panel through the full cell depth, so a wall slice becomes
# a solid cell block (rows of them read as a solid wall, not free-standing fins).
#
# Run:  ASSET_ROOT=<staged sources> tools/convert
#
# The slot and variant choices below are curation: which wall of the kit is the wall,
# which piece is the locked-door leaf. Edit them as the art is chosen; the scale and the
# resolution are not set here, they come from the kit.

# Dungeon brushes (styloo dungeon-asset-pack). The wall is a thin edge panel placed on the
# boundary between open and solid cells (rotated to face the open side); the beam is the
# corner post set where wall panels meet; the barred panel is the locked-door leaf.
#
# The floor is one 96-voxel (4-cell) module cut into four distinct cell tiles, one per
# corner cell. The engine cycles them by cell position (tilekit variants: floor.vox,
# floor2.vox, ...), so the ground stops reading as a stamped grid.
asset dungeon    dungeon/floor.fbx      content/tiles/dungeon/floor.vox     cell celloff=0,0
asset dungeon    dungeon/floor.fbx      content/tiles/dungeon/floor2.vox    cell celloff=24,24
asset dungeon    dungeon/floor.fbx      content/tiles/dungeon/floor3.vox    cell celloff=48,48
asset dungeon    dungeon/floor.fbx      content/tiles/dungeon/floor4.vox    cell celloff=72,72
asset dungeon    dungeon/walls_010.fbx  content/tiles/dungeon/wall.vox      cell
asset dungeon    dungeon/beam.fbx       content/tiles/dungeon/post.vox      offset=0.5,0,0.5
asset dungeon    dungeon/irondoor.fbx   content/tiles/dungeon/door.vox
asset dungeon    dungeon/ironwalls.fbx  content/tiles/dungeon/doorleaf.vox  cell surface

# The one stair flight serves both ways. The up-stair rises on the floor; the down-stair is
# the same flight rotated to descend, drawn sunk below the floor with the floor tile left
# off that cell, so it reads as a stairwell hole in the ground. Same mesh, two placements.
asset dungeon    dungeon/stair.fbx      content/tiles/dungeon/stairup.vox
asset dungeon    dungeon/stair.fbx      content/tiles/dungeon/stairdn.vox

# Player: the Ranger outfit (quaternius modular-character-outfits-fantasy), posed from the

# Monsters (quaternius lowpoly-animated-monsters). Each converts at the monsters-kit scale
# (skeleton 1.8 m) and is centred on the horizontal axes. The output file is the lower-cased
# monster content id (monsters.txt), which the engine loads per entity. Slime stands in for
# the grey ooze, the dragon for the demon lord. The rest of the bestiary (the humanoids and
# the kit-less creatures) stays on the drawn placeholder until a source is fitted.
asset monsters   monster/Skeleton.fbx  content/models/skeleton.vox  offset=0.5,0,0.5
asset monsters   monster/Slime.fbx     content/models/ooze.vox      offset=0.5,0,0.5
asset monsters   monster/Bat.fbx       content/models/bat.vox       offset=0.5,0,0.5
asset monsters   monster/Dragon.fbx    content/models/demon.vox     offset=0.5,0,0.5

# Easy enemies (quaternius animated-easy-enemies). A stylized kit not internally to scale:
# its creatures differ in native size, so each carries a per-asset scale factor on top of
# the shared enemies-kit scale, sized to its combat size class beside the 1.8 m hero. The
# giant rat and spider read as oversized vermin, the frog and serpent as human-height
# brutes, the wasp as a small but solid flier. OBJ sources used directly (the kit's 2019

# Humanoid foes (quaternius modular-character-outfits-fantasy). Each is a rigged outfit
# posed at an Idle clip retargeted from the Universal Animation Library (human/UAL1.glb),
# so it stands naturally instead of voxelizing in its bind (T) pose. The pose tool skins
# the glb; the voxelizer then samples the outfit's base-colour textures. Ranger is the
# bandit, male peasant the cultist, female ranger the acolyte.
#   pose <kit> <gltf> <animlib.glb> <clip> <time> <out.vox>
pose human      human/Male_Ranger.gltf    human/UAL1.glb  Idle_Loop  0.5  content/models/bandit.vox  darken=T_Ranger_BaseColor.png:0.4
pose human      human/Male_Peasant.gltf   human/UAL1.glb  Idle_Loop  0.5  content/models/cultist.vox
pose human      human/Female_Ranger.gltf  human/UAL1.glb  Idle_Loop  0.5  content/models/acolyte.vox
pose human      human/Female_Peasant.gltf human/UAL1.glb  Idle_Loop  0.5  content/models/witch.vox

# Fantasy-race foes (quaternius characters-fantasy-races). Rigged characters posed from UAL1
# like the outfits, but their GLB bakes the base-colour texture inside, so tex= points the
# posed material at the external image staged beside the mesh. Orc male/female are the orc and
# the ogre, elf male/female the dark elf and the elf archer.
pose races      races/Orc_Male.glb    human/UAL1.glb  Idle_Loop  0.5  content/models/orc.vox        tex=T_Orc_Male_BaseColor_1.png
